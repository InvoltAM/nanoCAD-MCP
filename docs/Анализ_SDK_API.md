# Анализ SDK nanoCAD 26 (M0)

**Источник:** NC_SDK_RU_26.0.7228.4926.8429 (из клуба разработчиков)
**Дата анализа:** 22.10.2026
**Вывод:** API достаточен для построения Electro-слоя без compile-time зависимости от DLL Электро.

## 1. Состав SDK

| Компонент | Содержимое | Ценность для проекта |
|---|---|---|
| `docs/` | CHM-справочники: MAPI_NET_ref (MultiCAD API), ncNET_ref, NRX_ref и др. | Полная документация API |
| `include-x64/` | Управляемые сборки + XML-документация: `hostmgd.dll`, `hostdbmgd.dll`, `mapimgd.dll` (+ `.xml`) | Сборка плагина; XML — машиночитаемая карта API |
| `samples/Mgd/` | Примеры .NET: HelloMultiCAD (параметрические объекты, помещения, отчёты, таблицы) | Эталонные паттерны кода |
| `samples/NRX/`, `samples/COM/`, `samples/Lisp/` | Примеры C++ и COM | Резервные каналы доступа |

## 2. Ключевые механизмы API (подтверждены XML-документацией и примерами)

### 2.1. Универсальный доступ к свойствам объектов — `ObjectProperties`

```csharp
// из samples/Mgd/HelloMultiCAD/Samples.cs
List<String> names = format.DbEntity.ObjectProperties.GetNames();
format.DbEntity.ObjectProperties["Designation"] = "Текст 1";
```

Любой объект в базе чертежа отдаёт `McProperties` — коллекцию свойств по имени
(`GetNames()`, индексатор на чтение и запись, `GetValueEx`).
**Это главная находка:** объекты BIM Электро (наследники `McCustomBase`)
можно читать и модифицировать, не зная их классов на этапе компиляции.

### 2.2. Выборка объектов — `ObjectFilter`

```csharp
// из samples/Mgd/HelloMultiCAD/SamplToRooms.cs
List<McObjectId> ids = ObjectFilter.Create(true)
    .AddType(McRoom.TypeID)          // фильтр по TypeID (Guid) или Type
    .GetObjects();
```

Поддерживаются фильтры: тип (Guid/Type/generic), слой, документ, лист,
габаритный контур (`SetBound`). TypeID объектов Электро извлечём
реверс-анализом её DLL (атрибут `CustomEntity("GUID", ...)`).

### 2.3. Параметрические объекты — `McCustomBase`

Пространства имён `Multicad.CustomObjectBase`, `Multicad.McObject`,
`Multicad.Runtime`. Классы вертикальных решений регистрируются атрибутом
`[CustomEntity("GUID", "Name", "Описание")]` и наследуют `McCustomBase`
(пример — `ObjectRefEntity` в BlocksAndRefs.cs). Значит, при необходимости
мы можем **создавать собственные электротехнические объекты** как полноценные
параметрические объекты платформы.

### 2.4. Помещения — `McRoom`

`SamplToRooms.cs`: чтение площади, контуров (`Loops`), события
(`McRoom.OnShowForm`). Закрывает модуль «Помещения» из ТЗ.

### 2.5. Отчётный движок — `McTable` с плейсхолдерами

Пример `smpl_CreateTableReport2` строит именно «Ведомость электророзеток
по номеру помещения»: шаблон таблицы с плейсхолдерами `#room`, `#code`,
секции данных/колонтитулов. На этом строим генерацию спецификаций,
кабельного журнала и ведомостей из нашей модели.

### 2.6. Команды и точки входа

- `[CommandMethod("name", CommandFlags.NoCheck | CommandFlags.NoPrefix)]` — регистрация команд;
- `IExtensionApplication` (Initialize/Terminate) — инициализация плагина при загрузке;
- `McObjectManager.SelectObjects(...)` — интерактивный выбор (для отладки);
- сериализация объектов: `McDbEntity.SerializeToBase64String()` — удобно для отладки чтения объектов Электро.

## 3. Чего в SDK нет (ожидаемо)

- Классов BIM Электро (поиск `electro*`/`электро*` по include-x64 и samples
  не дал результатов) — объекты Электро живут в DLL вертикального решения;
- Программного доступа к расчётному ядру и генераторам отчётов Электро —
  вопрос закрываем реверс-анализом DLL Электро и, при необходимости,
  своим расчётным модулем `electro_calc` (уже готов).

## 4. Архитектурное решение по итогам анализа

**Generic Property Adapter:** Electro-сервисы строим на связке
`ObjectFilter` (поиск по TypeID) + `ObjectProperties` (чтение/запись по имени)
без жёсткой ссылки на сборки Электро.

Плюсы:
- плагин компилируется только против SDK платформы (mapimgd.dll и др.);
- устойчивость к обновлениям Электро (имена свойств и GUID'ы — в конфиге, а не в коде);
- конфигурация маппинга (TypeID → тип объекта, имя свойства → поле DTO)
  выносится в JSON, что позволит адаптироваться под версии Электро без пересборки.

Минусы и митигация:
- имена свойств узнаём реверс-анализом DLL + дампом `ObjectProperties.GetNames()`
  на реальном проекте (первым же диагностическим инструментом
  `electro_dump_object` на этапе PoC).
