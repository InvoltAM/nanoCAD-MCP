### Создатели объектов (программное создание — подтверждено)

- `Creators.BoardCreator.Create()` — создание щита;
- `DbElFiderCraetor` (+интерфейс `IDbElFiderCraetor`):
  `Initialize()`, `CreateNewFider()`, `InsertFiders()`, `CopyContent()` —
  создание фидеров в базе чертежа программно.

### Сервисы

- `IElFiderService`, `FiderFillingService` — операции с фидерами;
- `ElLayerService` — управление слоями Электро;
- `ElTeEquipmentNumeratorService` — нумерация оборудования;
- `IKccService` — кривые силы света (светотехника);
- `ITechTaskServiceR2` — техническое задание;
- `ElBoardEtMenuProvider.IsAutoBalance` — автобалансировка фаз существует в продукте.

## 2. Проектный уровень (CAE.Project, 1.5 МБ — крупнейшая сборка)

- `IAppProjectService` — управление проектом;
- `ICaeNetViewService` — представление сетей;
- `ICaeContourService` — контуры (помещения/трассы);
- `CaeObjectHighlightService` — подсветка связей (пригодится для визуальной обратной связи агенту).

## 3. Генерация документации (ReportGenerator)

- `CaeTableGenerator` — табличные отчёты из CAE-модели (кабельный журнал, спецификации);
- `CaeDocumentGenerator` — документы;
- `CsvGenerator`, `Excel.ExcelOutput/ExcelSheet/ClosedXmlSession` — выгрузка в CSV/XLSX.

**Вывод:** генераторы отчётов программно доступны.

## 4. Итоговые выводы для архитектуры Electro-слоя

1. **Полный цикл программно закрываем штатными средствами:**
   создание (BoardCreator, DbElFiderCraetor) → наполнение (свойства ElFider/ElBoard)
   → расчёт (EsnPowerCalcFactory, светотехника) → проверки (CheckService)
   → документация (CaeTableGenerator/Excel).
2. **Два канала доступа к объектам:**
   - типизированный — прямые классы ESN (основной, где возможно);
   - универсальный — `ObjectProperties` + `ObjectFilter` из SDK (fallback и диагностика, `electro_dump_object`).
   Гибрид фиксируется в архитектуре: типизированные сервисы + generic-адаптер.
3. **electro_calc остаётся:** независимая проверка + офлайн-расчёты для агента
   без запущенного nanoCAD.
4. **Риск «закрытого API» снимается:** сотни публичных типов, DI-контейнер
   (атрибуты `[Component]`, `[Composer]`) — архитектура продукта открытая.

## 5. Открытые вопросы (этап PoC на Windows-машине)

- Точные сигнатуры: параметры `BoardCreator.Create()`, `CreateNewFider()` —
  извлечь дампом сигнатур (следующая итерация анализатора) или проверкой на живом nanoCAD;
- Регистрация сервисов в DI-контейнере Электро (как получить экземпляр сервиса из плагина);
- WireCommon (провода/трассы) — не входил в партию; запросить при необходимости;
- Имена GUID TypeID для ObjectFilter — извлечь на живом проекте через
  `electro_dump_object` (объекты Электро могут регистрироваться не через CustomEntity).
