## 1. Архитектура продукта

nanoCAD BIM Электро — **кросс-CAD продукт**: в AddIn обнаружены адаптеры
`ElNanoCadProtectionInformation`, `ElAutoCadProtectionInformation`,
`ElBricsCadProtectionInformation` — одно ядро работает на nanoCAD, AutoCAD и BricsCAD.
Сборки нацелены на .NET 6 (`System.Runtime 6.0.0.0`).

Слоистая структура:

```
Nanosoft.Electrica.AddIn      — интеграция с CAD-хостом, установщики
Nanosoft.Electrica.Core       — доменная логика: компоновка щитов, проверки
Nanosoft.Electrica.Calc       — расчётное ядро: нагрузки, освещение
Nanosoft.CAE.*                — объектная модель проекта (НЕ получены)

Nanosoft.ObjectLib.WireCommon — провода/кабели (НЕ получены)
Nanosoft.ReportGenerator      — генератор отчётов (НЕ получен)
Nanosoft.Platform / Evos.*    — внутренний фреймворк Нанософт
```

## 2. Electrica.Core — 175 публичных типов

### Компоновка щитов
- `ComposeShieldUnit`, `ComposeBoard`, `ComposeBox` (атрибут `[Composer]`) —
  автоматическая компоновка щита из аппаратов;
- `ElCaseNode`, `ElCaseRow` — структура корпуса щита.

### Встроенные проверки (CheckService) — готовая валидация модели
- `ElCheckWireLongLoadCurrent` — длительно допустимый ток проводника;
- `ElCheckConsumerAndGroupPhases` — соответствие фазности приёмников и групп;
- `ElCheckConnectionInputGroupOfShell` — связность ввод→группы в щите;
- `ElCheckCableOutEquip`, `ElCheckCableNotInVolume`, `ElCheckFiderConsumerGx` и др.

### Аппараты защиты как обёртки фидеров
`FiderWrapperIsSafeAutomat`, `FiderWrapperIsUzo`, `FiderWrapperIsFuse`,
`FiderWrapperIsKnifeSwitch`, `FiderWrapperIsStarter`,
`FiderWrapperIsFrequenceTransformer` + встроенные проверки:
`...IsAutMaxKzCheck`, `...IsAutMinKzCheck`, `...IsUzoLeakICheck`,
`...IsAutCurrentCheck`, `IsCableInstCurrentCheck`.

**Вывод:** значительная часть проверок из нашего electro_calc уже есть
в продукте — потенциально доступна для вызова.

## 3. Electrica.Calc — расчётное ядро (публичные классы!)

### Расчёт нагрузок (Pc-модель)
- `EsnPowerCalcFactory` / `IEsnPowerCalcFactory` — точка входа расчёта нагрузок;
- `PcSupply`, `PcGroup`, `PcFlatGroup` (квартирные группы!), `PcLightGroup`,
  `PcPowerGroup`, `PcEmergencyGroup`, `PcData`;
- `PowerCalcModeEnum` — режимы расчёта.

### Коэффициенты спроса по типам приёмников (Sg-модель)
`SgFridge`, `SgDishWasher`, `SgFood`, `SgEmergencyLight`, `SgEmergencyFire`,
`SgEmergencyReserve` — нормативные Кс зашиты в коде, соответствуют
нашей таблице DEFAULT_DEMAND_FACTORS в electro_calc.

### Светотехнический расчёт (полный контур)
- `LightEtaCalc` — метод коэффициента использования светового потока;
- `ElPointMethodLightCalculator` — точечный метод;
- `IsolineComplexCreator`, `Histogram` — изолинии и визуализация;
- `ElLightingCalcService`, `LightInstaller`.

### Прочее
- `CableSettingsContainer` — настройки кабелей;
- `ElCalcChecker` — контроль расчётов;
- `ProjectSettingService` — настройки проекта.

## 4. Предварительные выводы для архитектуры

1. **Вариант А ТЗ (мост к штатному расчётному ядру) выглядит достижимым:**
   `EsnPowerCalcFactory` и светотехнические сервисы публичны.
   Решение — после анализа CAE/ESN (нужны типы входных данных расчёта).
2. **Гибридная стратегия по проверкам:** штатные `ElCheck*` (Core) +
   наш electro_calc как независимый контроль и fallback.
3. **Объектная модель — в Nanosoft.CAE.* и Nanosoft.ObjectLib.ESN*:**
   именно там живут щиты, фидеры, приёмники как объекты базы чертежа
   с TypeID и ObjectProperties.
